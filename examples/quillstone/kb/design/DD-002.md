# DD-002: Row representation

## Context

Row-at-a-time objects were easy to use but slow; pure columnar APIs were fast but hard to use in small transforms.

## Decision

User code sees rows as plain objects; batches store columns internally and materialize rows lazily.

## Consequences

- Transforms written with `map` stay simple.
- Vectorized transforms can opt into the column view.
